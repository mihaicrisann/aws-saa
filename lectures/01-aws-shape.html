The shape of AWS

Regions, Availability Zones, edge locations, and who is responsible for what. Every later answer is a consequence of this geometry.

Design Resilient Architectures Design Secure Architectures Global infrastructure Shared responsibility Well-Architected

AWS is not one computer somewhere. It is a set of independent geographic units that you deliberately spread work across. Almost every "which design is more resilient / cheaper / faster" question on the exam is really asking whether you understand this layout — so learn it once, properly, and stop guessing.

Region → AZ → data centre

Three nested levels, and the exam cares about the boundary between each.

LevelWhat it isFailure boundary
Region
eu-west-1		A geographic area (Ireland, Frankfurt, N. Virginia…) containing 3+ AZs. Independent from every other Region.A Region-wide outage is rare but possible. Surviving it requires a second Region.
Availability Zone
eu-west-1a		One or more physical data centres with independent power, cooling and networking, kilometres apart but linked by low-latency (<1–2 ms) private fibre.An AZ can fail whole. Surviving it requires resources in 2+ AZs in the same Region.
Edge / PoP
600+ worldwide		Small sites that cache and terminate connections close to users. Used by CloudFront, Route 53, Global Accelerator, WAF, Shield.Not for running your workload — for shortening the distance to it.
The bit people miss

AZ letters are scrambled per account. My eu-west-1a and your eu-west-1a are probably different physical zones — AWS does this so everyone doesn't pile into "a". If you genuinely need to name the same physical zone across accounts, use the AZ ID (euw1-az2), which is stable.

Scope: the table worth memorising

Every service sits at exactly one scope. Getting this wrong is how you pick a wrong answer that "looks" right.

GlobalRegionalZonal (AZ-bound)
IAM, Route 53, CloudFront, WAF (for CloudFront), Organizations, Billing, S3 bucket namespace S3 buckets (data lives in one Region), DynamoDB, SQS, SNS, Lambda, VPC, ELB, KMS keys, most managed services EC2 instances, EBS volumes, subnets, RDS instances (a single DB instance lives in one AZ), NAT Gateway
Classic trap

An EBS volume can only attach to an instance in its own AZ. If a question moves an instance to another AZ, the volume does not follow — you snapshot it (snapshots are Regional, stored in S3) and create a new volume from the snapshot in the target AZ. Same trick appears for "copy an AMI to another Region".

Shared responsibility

AWS secures of the cloud; you secure in the cloud. The line moves depending on how managed the service is, and the exam uses that movement as a distractor.

Service styleAWS handlesYou handle
IaaS — EC2, EBS, VPCHardware, hypervisor, physical security, network fabricGuest OS + patching, firewall rules (SG/NACL), app code, encryption choices, IAM
PaaS — RDS, ECS on Fargate, EMROS and DB engine patching, underlying hostSchema, users/passwords, network placement, backup retention settings, IAM, encryption toggle
SaaS-ish — S3, DynamoDB, LambdaEverything under the API, durability, availabilityOnly: your data, who can reach it (IAM/policies), classification, and encryption settings

Two things are always yours, no matter how managed the service: IAM permissions and your data. If an answer option says AWS is responsible for configuring your security groups or rotating your database credentials, it is wrong.

Durability vs availability

The exam uses these words precisely, so you should too.

  • Durability — will the data still exist? S3's famous 11 nines (99.999999999%) is a durability figure: it survives losing multiple facilities because objects are replicated across ≥3 AZs.
  • Availability — can you reach it right now? S3 Standard targets 99.99% availability. Lower tiers like S3 One Zone-IA keep the same durability within one AZ but drop availability to 99.5%, because losing that AZ loses access — and if the AZ is destroyed, the data too.
Exam tip

"Must survive the loss of an Availability Zone" → spread across AZs. "Must survive the loss of a Region" → cross-Region replication, a second Region, or a global service. "Must never lose the data" → durability wording (replication, backups, versioning). Match the vocabulary and half the answers eliminate themselves.

Well-Architected: the six pillars

You will not be asked to recite these, but the exam is graded along them — the four exam domains are essentially four of these pillars.

PillarThe question it asks
Operational excellenceCan we run, observe and improve this? (small reversible changes, automate)
SecurityLeast privilege, encryption everywhere, traceability — exam domain 1, 30%
ReliabilityDoes it recover automatically? — exam domain 2, 26%
Performance efficiencyRight resource, right size, go serverless where you can — exam domain 3, 24%
Cost optimisationPay only for what you use, pick the cheapest thing that meets the requirement — exam domain 4, 20%
SustainabilityMinimise the resources consumed to do the job

The default design pattern

Hold this picture in your head. A large fraction of exam scenarios are a variation of it, and knowing the baseline tells you instantly what a question is changing.

Reading the picture
Anything internet-facing→Public subnet: ALB, NAT Gateway. Nothing else.
Compute and databases→Private subnets, always. Reached only via the ALB.
Every tier drawn twice→Two AZs minimum. That is what "highly available" means here.
State pushed sideways→S3 / DynamoDB / ElastiCache, so instances stay disposable.

Check yourself

An application must keep serving traffic if one data centre burns down. What is the minimum architecture?
Resources in at least two Availability Zones in one Region, behind a load balancer, with the database in Multi-AZ. A second Region is not required and would be the more expensive wrong answer if the requirement only says "data centre" or "Availability Zone".
Why can't you attach an EBS volume in eu-west-1a to an instance in eu-west-1b?
EBS is a zonal service — the volume lives on storage hardware inside one AZ. To move it: take a snapshot (Regional, backed by S3), then create a new volume from that snapshot in the target AZ.
A customer stores build artefacts they can regenerate in an hour. Cost matters more than availability. Which S3 class, and what is the risk?
S3 One Zone-IA — same 11-nines durability but only within a single AZ, at ~20% less than Standard-IA. The risk: if that AZ is lost, so is the data. Acceptable precisely because it is reproducible.
Who patches the operating system of an RDS instance? Who rotates its master password?
AWS patches the OS and DB engine (it is a managed service). You own the credentials — rotate them yourself, ideally via Secrets Manager. Data and identity are always yours.

Take away

  1. Region = independent geography; AZ = independent data centre(s); edge = caching close to users. Failure requirements map directly onto these three.
  2. Know each service's scope. Global (IAM, Route 53, CloudFront), Regional (S3, DynamoDB, Lambda), Zonal (EC2, EBS, subnets).
  3. AZ letters differ per account; AZ IDs do not.
  4. You always own your data and your IAM permissions, whatever the service.
  5. Durability = "does it still exist"; availability = "can I reach it". S3 One Zone-IA is the classic place they diverge.
  6. Memorise the two-AZ ALB → ASG → Multi-AZ RDS baseline. Most questions are a mutation of it.
