EC2 and what it costs

Instance families, the five purchasing models, placement groups, and instance metadata. Most cost questions on the exam live here.

Design Cost-Optimized Architectures Design High-Performing Architectures EC2 Savings Plans Spot Placement groups

EC2 is a virtual machine you rent by the second. The exam rarely asks you to configure one — it asks you to pick the right size, the right family, and above all the right billing model. Purchasing options are the single densest source of cost-domain questions.

Instance families

You do not need the full catalogue. You need the first letter and what it optimises for.

LetterClassReach for it when
tBurstable general purposeLow, spiky baseline — dev boxes, small sites. Earns CPU credits when idle, spends them when busy. Unlimited mode lets it burst past its credits for a surcharge.
mGeneral purposeBalanced CPU:memory. The safe default for app servers.
cCompute optimisedBatch, encoding, HPC, game servers, high request-rate web tiers.
r, x, zMemory optimisedIn-memory caches, large relational DBs, SAP HANA (x = highest RAM per vCPU).
i, d, imStorage optimisedVery high local IOPS — NoSQL, data warehouses, distributed file systems. Comes with instance store.
p, g, inf, trnAcceleratedGPU / ML training and inference.

Suffixes worth recognising: g = Graviton (ARM, ~20% better price/performance — the answer to "reduce cost without losing performance" when the workload can be recompiled), n = enhanced network bandwidth, d = local NVMe attached, a = AMD.

Dedicated Host vs Dedicated Instance

Both give you single-tenant hardware. Dedicated Instance = isolated hardware, but AWS controls placement and you get no visibility of sockets/cores. Dedicated Host = you get the actual physical server, see its sockets and cores, and control instance placement — which is what per-socket/per-core BYOL licensing (Windows Server, Oracle, SQL Server) requires. If a question says "existing licences tied to physical cores", the answer is Dedicated Host.

Savings Plans vs RIs, decided fast

Modern exam wording favours Savings Plans — they cover the same discount range with more flexibility, and Compute Savings Plans extend to Fargate and Lambda. Pick RIs only when the question stresses an unchanging instance type, or explicitly needs capacity reservation in a specific AZ (which a zonal RI gives and Savings Plans do not).

Spot, properly

  • You are interrupted when capacity is needed elsewhere, with a 2-minute warning in instance metadata / an EventBridge event.
  • Spot Fleet / EC2 Fleet requests capacity across many instance types and AZs, which is how you make Spot reliable. Strategy capacity-optimized minimises interruption; lowest-price minimises cost.
  • Spot blocks are gone. If a question needs a guaranteed uninterrupted window, Spot is wrong.
  • Standard pattern: an Auto Scaling group with a mixed instances policy — a base of On-Demand for the floor, Spot for the burst.

Placement groups

TypeLayoutBuys youCosts you
ClusterPacked into one rack, one AZLowest latency, 10 Gbps+ between nodes — HPC, tightly-coupled computeAll eggs one basket: a rack failure takes everything
SpreadDistinct hardware, can span AZs. Max 7 instances per AZMaximum isolation — small numbers of critical instancesHard 7-per-AZ limit
PartitionGroups of racks ("partitions"), each on separate hardwareLarge distributed systems that understand racks — HDFS, Cassandra, KafkaMore complex; app must be partition-aware

Metadata, user data, AMIs

  • User data runs once at first boot as root — bootstrapping. Bake stable parts into a golden AMI instead when the question complains about slow scale-out.
  • Instance metadata at http://169.254.169.254/latest/meta-data/ gives instance id, AZ, and (via the attached role) rotating credentials. Always prefer IMDSv2 (session token required) — it is the mitigation for SSRF attacks that read credentials from metadata.
  • AMIs are Regional. To launch in another Region you copy the AMI there. Encrypted AMIs need the target Region's KMS key.
  • EC2 Image Builder automates building, patching and testing golden AMIs on a schedule.
Stop vs hibernate vs terminate

Stop: RAM is lost, EBS root persists, you stop paying for compute (still pay for EBS). Public IPv4 changes unless it's an Elastic IP. Hibernate: RAM is written to the encrypted root EBS volume and restored on start — fast warm-up for long-loading apps; root volume must be encrypted and large enough for RAM. Terminate: root volume deleted by default (DeleteOnTermination), extra volumes retained by default.

Connecting without SSH

Modern exam answers avoid opening port 22 to the world:

Access patterns
Shell into a private instance, no bastion, no open ports→AWS Systems Manager Session Manager (needs the SSM agent + an instance role)
Browser-based SSH from the console→EC2 Instance Connect (public instances; pushes an ephemeral key)
Run one command across 500 instances→SSM Run Command
Audit every shell session→Session Manager logging to S3 / CloudWatch Logs

Check yourself

A nightly video transcoding job takes 4 hours, is fully checkpointed, and can restart. Cheapest option?
Spot Instances, ideally via an EC2 Fleet across several instance types with the capacity-optimized strategy. Interruptible + fault-tolerant + flexible timing is the exact Spot signature.
Steady 24/7 fleet, but the team plans to migrate some services to Fargate this year. Which commitment?
Compute Savings Plan — it applies across EC2 family/size/Region and Fargate and Lambda, so the discount survives the migration. An EC2 Instance Savings Plan or a Standard RI would strand the commitment.
Oracle licences are counted per physical CPU socket. What do you launch on?
Dedicated Hosts — the only option exposing physical sockets and cores and letting you control placement, which is what socket-based BYOL requires.
Scale-out takes 8 minutes because user data installs a long dependency chain. Fix?
Bake the dependencies into a golden AMI (built with EC2 Image Builder), leaving user data to do only per-instance configuration. Boot drops to well under a minute. Optionally add ASG warm pools.

Take away

  1. Family by first letter: t burstable, m balanced, c compute, r/x memory, i storage, p/g GPU. Graviton (g) is the cheap-and-fast answer.
  2. Interruptible + stateless + flexible timing → Spot. Steady + maybe changing → Compute Savings Plan. Socket-bound licences → Dedicated Host.
  3. Cluster = low latency, spread = isolation (7/AZ), partition = rack-aware distributed systems.
  4. Slow scale-out from user data → golden AMI.
  5. Private shell access → Session Manager, not a bastion with port 22 open.
  6. Enforce IMDSv2; AMIs and EBS snapshots are Regional and must be copied to be used elsewhere.
