S3, properly

Storage classes, lifecycle, versioning, encryption, access control, and performance. Expect S3 in a fifth of your questions.

Design Cost-Optimized Architectures Design Secure Architectures Design High-Performing Architectures S3 Glacier Lifecycle Bucket policy

S3 is object storage: flat, effectively infinite, reached over HTTPS by key. It shows up in roughly a fifth of exam questions and in all four domains, so this is the longest lecture here. The four things worth genuinely knowing: storage classes, lifecycle, access control, and encryption.

The model

  • Buckets have globally unique names and live in one Region. Objects up to 5 TB.
  • There are no real folders. reports/2026/q1.csv is one flat key that happens to contain slashes; the console fakes directories using the prefix.
  • Writes are strongly consistent — read-after-write for PUTs, LISTs and DELETEs. (Old exam material claiming eventual consistency is out of date; ignore any answer that hinges on it.)
  • Uploads over 100 MB should use multipart upload (mandatory above 5 GB): parallel parts, resumable, faster. Add a lifecycle rule to abort incomplete multipart uploads — otherwise you pay for orphaned parts forever.

How class questions are actually decided

Read for two facts: how fast must it come back, and do we know the access pattern. "Milliseconds" kills every Glacier tier except Instant Retrieval. "Unpredictable / unknown access" → Intelligent-Tiering. "Regulatory retention for 7 years, retrieval within 12 hours acceptable" → Deep Archive. "Can be regenerated" unlocks One Zone-IA. Minimum-duration charges are why moving objects to IA after 3 days is a wrong answer.

Lifecycle rules

Rules apply to a prefix or tag and do two kinds of thing: transition (change class) and expiration (delete). They can act on current versions, on noncurrent versions, on delete markers, and on incomplete multipart uploads.

logs/   day 0    Standard
        day 30   → Standard-IA
        day 90   → Glacier Flexible Retrieval
        day 365  → Glacier Deep Archive
        day 2555 → expire (delete)

noncurrent versions: → Glacier after 30d, delete after 90d
incomplete multipart uploads: abort after 7d
Transitions only go downhill

Lifecycle can move objects to colder classes, never back up. To restore something from Glacier you issue a restore request, which makes a temporary copy available for N days. Also: you cannot transition to a class before its minimum duration would make sense, and objects smaller than 128 KB are not transitioned to IA by default because it would cost more.

Versioning, locking, replication

  • Versioning is per bucket, and once enabled can only be suspended, never removed. Deleting an object writes a delete marker; the old versions remain (and you keep paying for them — pair with a noncurrent-version lifecycle rule).
  • MFA Delete requires MFA to permanently delete a version or suspend versioning. Only the bucket owner (root) can enable it.
  • S3 Object Lock = WORM. Governance mode: special permission can override. Compliance mode: nobody, including root, can delete until the retention expires — the answer for "regulatory requirement that data cannot be altered or deleted". Legal hold is an indefinite lock with no date.
  • Replication (CRR across Regions, SRR within one) needs versioning on both buckets and an IAM role. It is asynchronous, replicates only new objects unless you run S3 Batch Replication for existing ones, and does not chain (A→B→C does not propagate A to C). RTC gives a 15-minute replication SLA.

Uses: CRR for cross-Region DR, lower latency for a distant office, and compliance separation. SRR for aggregating logs into one bucket or replicating prod into a test account.

Access control

MechanismUse
Block Public AccessOn by default at account and bucket level. Overrides everything else. The first thing to check in "why is my bucket not public" and the fix for "prevent accidental exposure".
Bucket policyThe main tool. Resource-based, supports cross-account, conditions like aws:SourceVpce, aws:PrincipalOrgID, aws:SecureTransport, s3:x-amz-server-side-encryption.
IAM policiesPer-identity permissions. Same-account access needs an Allow on one side; cross-account needs both.
Presigned URLsTime-limited link giving one person temporary GET or PUT rights, using your credentials. The answer for "let a user download a private file without giving them AWS credentials".
Access PointsNamed endpoints each with their own policy — how you avoid one 20 KB bucket policy for 50 teams. Object Lambda Access Points transform data on the way out (redact PII, resize).
ACLsLegacy. Disabled by default now (Bucket Owner Enforced). Do not pick unless the question is explicitly about legacy per-object ownership.
The static-website distinction

Two ways to serve a static site. S3 website endpoint + public bucket: simple, HTTP only, needs Block Public Access off. CloudFront + private bucket + Origin Access Control (OAC): HTTPS, custom domain, caching, WAF, and the bucket stays fully private. The exam wants OAC every time security or HTTPS is mentioned. OAC replaces the older OAI.

Performance and cost levers

  • S3 scales to 3,500 PUT/COPY/POST/DELETE and 5,500 GET/HEAD per second per prefix. More throughput → spread keys across more prefixes. (Random hash prefixes are no longer required, but multiple prefixes still parallelise.)
  • Transfer Acceleration routes uploads over the AWS backbone via an edge location — the answer for "users worldwide upload large files to one bucket, slowly".
  • Byte-range fetches parallelise big downloads or grab just a file header.
  • S3 Select retrieves a subset of an object with SQL, cutting transfer. For querying across many objects, that's Athena.
  • Requester Pays shifts data transfer cost to the downloader — for sharing large datasets.
  • Storage Lens (org-wide analytics) and Storage Class Analysis (which objects to transition) are the "how do we find savings" answers.
  • S3 Batch Operations runs an action (copy, tag, restore, invoke Lambda) over billions of objects from a manifest.
  • Data into S3 is free; data out to the internet is the expensive direction. Serving through CloudFront is cheaper than serving from S3 directly.
Event-driven S3

S3 Event Notifications fire on object created/removed/restored and target Lambda, SQS or SNS. For richer filtering and more targets, route them through EventBridge instead. This is the backbone of "process each uploaded file" scenarios.

Check yourself

Regulator: financial records must be retained 7 years and must be impossible to delete, even by an administrator.
Versioning + S3 Object Lock in Compliance mode with a 7-year retention period, on objects stored in Glacier Deep Archive for cost. Governance mode would be wrong — it can be overridden by a privileged user.
Access patterns for a new data set are completely unknown. Minimise cost without risking latency.
S3 Intelligent-Tiering. It moves objects between frequent/infrequent/archive tiers automatically, with no retrieval fees and millisecond access in the instant tiers. Guessing Standard-IA risks retrieval charges on data that turns out to be hot.
You must let a customer upload one file directly to a private bucket, and they have no AWS account.
Generate a presigned PUT URL with a short expiry. No bucket policy change, no public access, no credentials handed out.
A static site must be HTTPS on a custom domain, and the bucket must not be public.
CloudFront in front of the bucket with Origin Access Control, an ACM certificate in us-east-1, and Route 53 alias records. Block Public Access stays fully on.
Why might moving log files to Standard-IA after 3 days increase the bill?
Standard-IA has a 30-day minimum billable duration (and a per-GB retrieval fee, and a 128 KB minimum billable size). Objects deleted before 30 days are still charged for 30. Transition at day 30 or use Intelligent-Tiering.

Take away

  1. Class choice = required retrieval speed × known-ness of the access pattern. Unknown → Intelligent-Tiering.
  2. Minimum durations (IA 30d, Glacier 90d, Deep Archive 180d) are what make otherwise-tempting lifecycle answers wrong.
  3. Object Lock Compliance mode is the only true "nobody can delete this" answer.
  4. Cross-Region Replication needs versioning both sides, is async, and does not backfill existing objects without Batch Replication.
  5. Private bucket + CloudFront + OAC is the standard secure delivery answer; presigned URLs handle one-off access.
  6. SSE-KMS when you need key control and an audit trail; add S3 Bucket Keys to control the cost.
  7. 3,500 writes / 5,500 reads per second per prefix; Transfer Acceleration for distant uploads; CloudFront to cut egress cost.
