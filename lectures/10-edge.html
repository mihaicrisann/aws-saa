The edge: DNS, CDN, anycast

Route 53 routing policies, CloudFront behaviours and origin protection, and when Global Accelerator beats a CDN.

Design High-Performing Architectures Design Resilient Architectures Route 53 CloudFront OAC Global Accelerator

Three services live between your users and your Region: Route 53 decides which address they get, CloudFront caches content near them, and Global Accelerator shortens the network path. They are frequently offered as alternatives to each other, so the distinction matters.

Route 53 record types

  • A / AAAA — name to IPv4 / IPv6.
  • CNAME — name to another name. Cannot be used at the zone apex (example.com), only on subdomains.
  • Alias — a Route 53 extension pointing at an AWS resource (ALB, CloudFront, S3 website, API Gateway, another record). Works at the apex, resolves to the resource's current IPs automatically, and queries are free. Whenever a question has example.com pointing at an ALB or CloudFront, the answer is an alias record, never a CNAME.
  • TTL controls how long resolvers cache. Long TTL = cheaper and faster, slower failover. Alias records to AWS resources use the target's TTL.

Latency vs geolocation

They sound similar and answer different questions. Latency-based optimises speed — a user in Poland may be sent to Ireland if that's faster. Geolocation enforces where traffic must go regardless of speed — the answer whenever the requirement mentions regulation, residency, licensing or language.

Health checks monitor an endpoint, another health check (calculated), or a CloudWatch alarm. Combine with failover records for automatic DNS-level DR. Note DNS failover is only as fast as the TTL, so lower it (60 s) when a question demands quick failover.

Hosted zones: public (internet-resolvable) and private (resolves only inside associated VPCs — this is how internal names like db.internal work). Route 53 is also a domain registrar, and Route 53 Application Recovery Controller is the heavyweight answer for readiness checks and routing controls in multi-Region DR.

CloudFront

A CDN with 600+ edge locations. Caches responses, terminates TLS at the edge, and shortens the TCP/TLS handshake even for content it cannot cache.

ConceptWhat it does
OriginS3 bucket, ALB, EC2, API Gateway, or any HTTP server — including on-premises
BehaviourPath pattern → origin + caching + policies. /api/* to the ALB with caching off; /* to S3 with a long TTL
Cache policyWhich headers/cookies/query strings form the cache key. Fewer keys = higher hit ratio
Origin Access Control (OAC)Lets CloudFront read a private S3 bucket. Replaces the older OAI. Always the right answer for securing an S3 origin

Signed URLs / cookiesTime-limited access to private content. URL = one file; cookie = many files (a whole video library)
Price classesLimit which edge locations are used to cut cost, at the expense of distant users
Origin groupsAutomatic failover to a secondary origin on error — origin-level HA
Geo restrictionAllow/deny countries at the edge
S3 presigned URL vs CloudFront signed URL

Both grant temporary access to private content. S3 presigned: simple, per-object, no CDN, served from the bucket's Region. CloudFront signed: cached and served from the edge, supports cookies for whole sets of files, and lets the bucket stay entirely private behind OAC. If the scenario involves media delivery to a global audience, pick CloudFront.

CloudFront also cuts cost: egress through CloudFront is cheaper than straight S3/EC2 egress, and cache hits never touch the origin. It integrates with WAF and Shield, which is the standard DDoS/L7 protection posture.

Global Accelerator

Gives you two static anycast IP addresses advertised worldwide. User traffic enters the AWS backbone at the nearest edge and is routed privately to the healthiest endpoint (ALB, NLB, EC2, Elastic IP) in whichever Region you configure. It does not cache.

The failover distinction worth a mark

Route 53 failover depends on DNS caching — clients keep the old answer until the TTL expires, so failover takes at least a minute and often longer with badly-behaved resolvers. Global Accelerator's IPs never change, so it reroutes at the network layer within seconds. "Fast regional failover without relying on DNS" is unambiguously Global Accelerator.

Check yourself

example.com must point at an Application Load Balancer.
A Route 53 alias A record to the ALB. CNAMEs are not allowed at the zone apex, and alias queries are free and track the ALB's changing IPs.
A multiplayer game server needs the lowest possible UDP latency worldwide and instant failover between Regions.
AWS Global Accelerator. CloudFront is HTTP-only and caching is irrelevant here; Route 53 latency routing still depends on DNS TTLs for failover.
German user data must be served only from eu-central-1 for legal reasons.
Geolocation routing. Latency-based routing could legitimately send a German user to Ireland, which breaks the requirement.
Video files must be viewable only by paying subscribers, delivered fast globally, from a bucket that stays private.
CloudFront with OAC to the private bucket, and signed cookies issued after login so one authorisation covers the whole library.

Take away

  1. Apex domain to an AWS resource → alias record, always.
  2. Latency routing = fastest. Geolocation = legally required location. Weighted = canary. Failover = active-passive.
  3. CloudFront caches HTTP; use OAC to keep S3 origins private and signed URLs/cookies for paid content.
  4. Versioned filenames beat invalidations.
  5. Global Accelerator: static anycast IPs, any TCP/UDP, no caching, seconds-fast failover independent of DNS.
  6. Both CloudFront and Global Accelerator move traffic onto the AWS backbone early — that alone is often the performance win.
