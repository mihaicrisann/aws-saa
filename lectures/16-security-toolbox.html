KMS and envelope encryption

KMS holds KMS keys (formerly CMKs) inside FIPS 140-2 validated hardware. The private key material never leaves. Because KMS only encrypts payloads up to 4 KB, everything real uses envelope encryption:

1. Ask KMS for a data key           → you get {plaintext key, encrypted key}
2. Encrypt your file locally with the plaintext key   (fast, any size)
3. Throw away the plaintext key; store the encrypted key beside the file
4. To decrypt: send the encrypted key to KMS (Decrypt), get the
   plaintext key back, decrypt the file locally
Key typeRotationNotes
AWS managed (aws/s3)Automatic, yearlyFree. No control over the key policy.
Customer managedOptional automatic yearly, or on demandYou write the key policy, can disable, schedule deletion (7–30 day waiting period), and audit every use in CloudTrail. Choose this whenever the question mentions control, rotation, or audit.

Key policies are not optional

A KMS key's key policy is the primary access control — unlike most services, an IAM policy alone is not enough unless the key policy delegates to IAM. This is why cross-account access to an encrypted S3 object needs three permissions: the bucket policy, the caller's IAM policy, and the KMS key policy. Also note KMS keys are Regional — copying an encrypted snapshot or AMI to another Region re-encrypts it with a key in the destination Region (multi-Region keys exist for the cases where you need the same key both places).

Reading DDoS questions

"Protect against SQL injection" → WAF. "Protect against a large volumetric DDoS with expert support and billing protection" → Shield Advanced. "Apply the same WAF rules to 40 accounts automatically" → Firewall Manager. Shield Standard needs no action and is never something you "enable".

Threat detection

ServiceOne-line identity
GuardDutyContinuous threat detection from CloudTrail, VPC Flow Logs and DNS logs. Finds crypto-mining, compromised credentials, port scans, communication with known-bad IPs. Agentless, one click. Cue: "detect malicious or unauthorised behaviour".
InspectorVulnerability scanning of EC2, ECR images and Lambda — unpatched CVEs and unintended network exposure. Cue: "scan for software vulnerabilities".
MacieUses ML to find sensitive data (PII) in S3. Cue: "discover personally identifiable information".

DetectiveInvestigates a finding — builds the graph of what happened and when.

ArtifactDownloads AWS's own compliance reports (SOC, ISO, PCI).

Those four cue words — threat → GuardDuty, vulnerability → Inspector, PII → Macie, aggregate → Security Hub — are worth memorising verbatim. They are asked almost word-for-word.

Cognito

  • User Pools = a user directory. Sign-up, sign-in, MFA, password policies, social and SAML/OIDC federation. Issues JWTs, and integrates natively with API Gateway and ALB for authentication. Cue: "authenticate application users".
  • Identity Pools = exchanges an identity (from a user pool, Google, Facebook, SAML, or unauthenticated guest) for temporary AWS credentials, so a mobile app can talk directly to S3 or DynamoDB with fine-grained per-user permissions.
Cognito vs IAM Identity Center

Cognito is for your application's end users — the customers of the app you build. IAM Identity Center is for your workforce signing into AWS accounts. Questions are unambiguous once you spot which population is being described.

Check yourself

Compliance requires keys in dedicated single-tenant hardware that AWS cannot access.
CloudHSM. Standard KMS is multi-tenant and AWS operates it; even customer-managed KMS keys don't satisfy a "AWS must have no access" clause.
An account is mining cryptocurrency after a credential leak. Which service would have flagged it?
GuardDuty — it detects crypto-mining, anomalous API calls and traffic to known-bad destinations from CloudTrail, Flow Logs and DNS logs, with no agents.
A mobile app must let users log in with Google and then upload directly to their own S3 prefix.
Cognito Identity Pool federating Google, handing back temporary AWS credentials scoped by an IAM role whose policy uses ${cognito-identity.amazonaws.com:sub} in the S3 prefix — each user reaches only their own folder.
A cross-account role can read the bucket policy-wise, but GetObject still returns access denied on KMS-encrypted objects.
The KMS key policy must also allow that role to kms:Decrypt. Encrypted S3 objects need bucket policy + IAM policy + key policy to all agree.

Take away

  1. Envelope encryption: KMS protects the small data key, the data key protects the large payload.
  2. Customer-managed KMS keys for control, rotation and CloudTrail auditing; CloudHSM only for dedicated single-tenant hardware requirements. Key policies are mandatory, and keys are Regional.
  3. Secrets Manager rotates; Parameter Store is free. ACM is free, auto-renewing, and must be in us-east-1 for CloudFront.
  4. WAF = layer 7 rules; Shield Advanced = big DDoS + response team + cost protection; Firewall Manager = apply either org-wide.
  5. GuardDuty (threats), Inspector (vulnerabilities), Macie (PII), Security Hub (aggregation). Memorise the four cue words.
  6. Cognito for app users; IAM Identity Center for your workforce.
