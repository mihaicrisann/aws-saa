Designing for cost

Where the money actually goes, the levers per service, and the cost-management tools the exam names by title.

Design Cost-Optimized Architectures Savings Plans Data transfer Cost Explorer Budgets S3 lifecycle

The cost domain is 20% of the exam and the easiest to score on, because cheap answers follow patterns. This lecture is the pattern list: where money goes, the lever per service, and the tools the exam names.

Where the money actually goes

  1. Compute hours — usually the largest line. Reduced by right-sizing, commitments, Spot, and scaling to zero.
  2. Data transfer out — the sneaky one. Inbound is free; outbound to the internet costs; cross-AZ traffic costs in both directions; cross-Region costs; traffic within an AZ using private IPs is free.
  3. Storage — driven by class and by everything you forgot: old snapshots, unattached EBS volumes, noncurrent S3 versions, incomplete multipart uploads, unassociated Elastic IPs, and now all public IPv4 addresses.
  4. Managed service premiums — NAT Gateway hours + per-GB processing, interface endpoint hours, provisioned IOPS, provisioned concurrency.
Data transfer, in one line each

In → free. Out to internet → expensive. Between AZs → charged both directions. Within an AZ over private IPs → free. Through CloudFront → cheaper than direct egress. Through a gateway endpoint to S3/DynamoDB → free and bypasses NAT. Over Direct Connect → much cheaper per GB than internet egress.

The lever per service

ServiceCheapest correct move
EC2Right-size first (Compute Optimizer), then Graviton, then commit with a Compute Savings Plan, then Spot for anything interruptible. Stop non-production instances out of hours with an EventBridge schedule.
Auto ScalingScale in aggressively; use a mixed-instances policy with Spot; scale to a minimum that matches real off-peak demand.
LambdaTune memory — more memory means more CPU and can cut total cost by finishing faster. Remove unused provisioned concurrency. Use ARM/Graviton.
S3Lifecycle to IA / Glacier / Deep Archive; Intelligent-Tiering when patterns are unknown; expire noncurrent versions; abort incomplete multipart uploads; use Storage Lens and Storage Class Analysis to find the fat.
EBSgp2 → gp3 (~20% cheaper, IOPS independent of size). Delete unattached volumes and stale snapshots; automate retention with Data Lifecycle Manager.
RDS / AuroraReserved Instances for steady databases; Aurora Serverless v2 for spiky or dev workloads; stop non-prod instances; right-size before committing.
DynamoDBProvisioned + auto scaling for predictable traffic (much cheaper than on-demand); TTL to delete expired items free; avoid Scans.
NetworkingGateway endpoints instead of NAT for S3/DynamoDB; keep chatty traffic within an AZ; CloudFront in front of S3/ALB; release unused Elastic IPs.
AnalyticsAthena over Parquet, compressed and partitioned — often a 90%+ reduction in scanned bytes. Redshift RIs or Serverless. EMR task nodes on Spot.
LogsSet CloudWatch Logs retention (the default is forever) and archive to S3.

The cost tools, by the question they answer

ToolAnswers
Cost Explorer"Where did the money go, and what will it be next month?" Visualise and forecast; also recommends RIs and Savings Plans.
AWS Budgets"Alert me when spend or usage crosses a threshold, or when the forecast will." Can trigger actions such as applying a restrictive IAM policy.
Cost and Usage Report (CUR)"Give me every line item for analysis" — delivered to S3, queried with Athena/QuickSight.
Cost Allocation Tags"Which team/project/environment spent this?" Activate them in the billing console; tag everything.
Compute Optimizer"Are these instances/volumes/functions the right size?" — machine-learning right-sizing recommendations.
Trusted Advisor"Find idle resources, low utilisation, unassociated EIPs" — cost checks alongside security and fault-tolerance ones.
Cost Anomaly Detection"Tell me when spend behaves unusually" — ML-based, alerts on anomalies.
Pricing Calculator"Estimate this architecture before we build it."
Billing ConductorCustom chargeback rates for internal billing.
Budgets vs Cost Explorer

They're often both offered. Cost Explorer analyses what happened; Budgets alerts on thresholds. If the requirement contains the word "notify", "alert" or "threshold", the answer is AWS Budgets.

Cost patterns the exam loves

Scenario → answer
Dev/test instances idle overnight and at weekends→Stop them on an EventBridge schedule (Instance Scheduler)
Archive that must be kept 7 years, retrieval in hours is fine→S3 Glacier Deep Archive via a lifecycle rule
Fault-tolerant batch processing→Spot, via EC2 Fleet or AWS Batch
Big NAT Gateway data-processing charges to S3→Free S3 gateway endpoint
Steady 24/7 baseline for the next 3 years→Compute Savings Plan (or RIs if the type is fixed)
Unknown S3 access patterns→Intelligent-Tiering
Serving lots of static content from S3/EC2→CloudFront — cheaper egress plus origin offload
Which team is spending what?→Cost allocation tags + Cost Explorer

Check yourself

A company runs 200 gp2 volumes sized purely for IOPS. Cut cost with no performance loss.
Migrate to gp3 and provision IOPS separately from capacity, shrinking the volumes to their actual data needs. gp3 is also about 20% cheaper per GB, and includes 3,000 IOPS baseline free.
The bill spikes and nobody notices for three weeks.
AWS Budgets with actual and forecasted alerts to SNS, plus Cost Anomaly Detection. Use Cost Explorer afterwards to work out what drove it.
An Athena query over a year of JSON logs costs far too much per run.
Athena charges per TB scanned. Convert to Parquet (columnar), compress, and partition by date so queries scan only the relevant partitions and columns. Typically a 90%+ cost reduction.
An application makes constant cross-AZ calls between its tiers. Where's the waste?
Cross-AZ data transfer is charged in both directions. Keep chatty tiers zone-local where resilience allows (or accept it as the price of multi-AZ), and use gateway endpoints and caching to cut the volume.

Take away

  1. Right-size before you commit; commit with a Compute Savings Plan; use Spot for anything interruptible.
  2. Data transfer out and cross-AZ traffic are the hidden costs; gateway endpoints and CloudFront are the standard fixes.
  3. S3 lifecycle + Intelligent-Tiering + expiring old versions covers most storage savings.
  4. gp2 → gp3, always. Delete unattached volumes, stale snapshots and idle Elastic IPs.
  5. "Alert on spend" → Budgets. "Analyse spend" → Cost Explorer. "Right-size" → Compute Optimizer. "Attribute spend" → cost allocation tags.
  6. Non-production should not run at 3 a.m. Schedule it off.
